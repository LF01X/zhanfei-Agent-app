## 1. 设计决策

### 1.1 为什么需要活动动态

AI Agent 领域高度依赖线下/线上活动传播。活动信息散落在各平台（Meetup、Eventbrite、GitHub Events），没有统一入口。

展飞作为 AI Agent 领域的 Understanding Engine，活动动态是"理解"的一部分——不是信息聚合，是**帮用户判断哪个活动值得参加**。

### 1.2 为什么先开放、后规范

当前展飞用户数为 0，活动主办方为 0。

在此阶段：
- 不做复杂审核流程
- 不做硬频率限制
- 不写"教科书式"安全规则（Next.js 框架已处理）

后续根据实际数据调整。

### 1.3 频率限制决策

**当前：不做硬限制。**

理由：
- 没有数据支撑合理的限制数字
- 过度限制会阻止早期主办方接入
- 发现滥用后，再根据实际模式设置限制

后续接入：
- 单 apiKey 频率限制（根据实际数据设定阈值）
- IP 级别频率限制

## 2. 主办方接入

### 2.1 当前阶段（手动）

```
1. 主办方在 GitHub 提 Issue
   标题：[活动提交] AI Agent Meetup Shanghai
   内容：活动名称、类型、时间、地点、描述、报名链接

2. 展飞手动录入 events.json
   验证信息真实性后录入

3. 展示在活动动态流
```

### 2.2 后续阶段（API）

```
1. 主办方申请 apiKey（GitHub Issue 或邮件）
2. 人工审核通过后发放
3. 主办方通过 POST /api/events 推送
4. 首次提交需人工审核，后续自动展示
```

---

## 3. 验证规则

| 规则 | 说明 |
|------|------|
| 必填字段 | `eventName`、`type`、`time`、`organizer`、`description`、`url` |
| `type` 枚举 | `online` / `offline` / `hybrid` |
| `time` | ISO 8601，未来时间，不超过 365 天后 |
| `url` | 必须 `https://` |
| `location` | `type` 为 `offline` 或 `hybrid` 时必填 |
